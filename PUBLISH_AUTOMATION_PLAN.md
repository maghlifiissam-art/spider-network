# Publish Spider: account and quality gates (Sep 2026)

The public `publish_spider.py` is **video-only**, not a Gumroad listing publisher. `config/publish.yaml` intentionally remains `dry_run: true`. The book workflows are separate and must not run merely because a platform token exists: today they create LLM text and publish with no independent originality, legal/factual, accessibility, layout or buyer-file review, and may commit generated files to this public repository. This is not a safe production handoff. Never turn off dry-run globally without validating each destination and credential.

## Digital products: Gumroad

Gumroad's official API at https://gumroad.com/api requires `edit_products` for product and file operations. In the seller's authenticated account, create a scoped token; store it as `GUMROAD_ACCESS_TOKEN` in a private runtime secret store, not Git or an Actions input/log. Do not send the token in chat. A product create should set `draft=true` explicitly; after upload and attachment, GET `/v2/products/:id` and verify the actual file list, metadata, price, correct product identity, and `published=false`. Once the reviewed deliverable passes originality, copyright, legal/factual, readability and file-open checks, POST `/v2/products/:id/enable`; GET the product and public page to confirm it is buyable and the buyer gets the intended file. Never retry a timed-out product create blindly: search existing products for duplicate name/slug first. Failure leaves the item draft and reports its product ID. International pricing defaults to $9 USD, not the existing auto-book workflow's $5; the Morocco 30 MAD Tally route is separate.

The existing `gumroad_publish.py` is a helper, not a complete production scheduler. A separate runner must consume a reviewed, ready-for-sale artifact and idempotent job ID, route to the chosen account and price, save receipts privately, and stop before publication if QA or payout requirements fail. Build and test that runner first. No automatic LLM-generated guide should be published until there is an actual content review, not a boolean supplied by the generation step itself.

## Social video channels

* Facebook Page: the user must own/manage the exact Page, and an app must have a Page access token with Pages publishing rights. Meta's current Pages API docs (https://developers.facebook.com/docs/pages-api/posts/) name `pages_manage_posts`, `pages_read_engagement`, `pages_manage_engagement`, `pages_read_user_engagement`, and `publish_video` for Page video. Use the Page, never a personal-profile browser automation workaround. Verify exact Page ID, scopes, app mode and a harmless test before enabling. This repo's publisher only supports video; link posts need a distinct `/PAGE_ID/feed` adapter and receipts.
* Instagram Reels: a Professional account must be connected to the intended Facebook Page for this code's Facebook Login route. Obtain `instagram_basic`, `instagram_content_publish`, `pages_read_engagement` and Page access token; verify IG account ID. Meta fetches media from a publicly reachable URL. Provide approved temporary hosting or implement Meta resumable video upload, wait for the container to be ready, publish it, then read back the permalink. Official requirements: https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/content-publishing/ . Current adapter lacks container readiness polling and invents a permalink from the media ID; don't report that URL as verified.
* TikTok: app registration and OAuth `video.upload` allow an inbox/draft upload for the owner to finish. Fully public direct post requires `video.publish` authorization and TikTok audit; unaudited direct posts remain private. https://developers.tiktok.com/doc/content-posting-api-get-started . Access tokens expire within 24h; refresh tokens can rotate and must be stored securely, so the current static `TIKTOK_ACCESS_TOKEN` adapter is not unattended automation: https://developers.tiktok.com/doc/oauth-user-access-token-management .
* YouTube: current code requires client ID/secret and upload refresh token. New unverified API projects upload videos private until audit: https://developers.google.com/youtube/v3/docs/videos/insert . No promise of public auto-publish before audit and consent/account verification.

For every channel, verify exact destination account and visible result with a readback URL, avoid duplicate posts after uncertain responses, and keep delivery receipts private. The AliExpress bot wall is not an alternate login route. No spend or purchases are needed for the research plan, but platform approvals and credentials still require the owner's account setup.
