# TikTok official publishing setup, not yet live

The account to authorize is the owner's actual Nexa Stories creator account, not the developer login. Verify the selected account's handle in the consent screen and bind its returned `open_id` as `TIKTOK_EXPECTED_OPEN_ID` before any upload. There is no developer login or app approval confirmed yet. TikTok's developer portal at https://developers.tiktok.com/login currently requires a separate email/password. Ask the owner which email owns that developer account, or which email to use for a new one; collect any new persistent password by secure vault link, not chat.

## Registration before OAuth

Official guide: https://developers.tiktok.com/doc/getting-started-create-an-app . Register an app, add Content Posting API, request only the needed scopes (`video.upload` for inbox drafts, `video.publish` for direct posting), configure an actual HTTPS redirect and verify ownership of the app website/Privacy/Terms URLs. Submit the required review evidence/demo. No app key/secret should be saved in Git, a README, Actions input, or chat. Official TikTok review can reject or delay the app: https://developers.tiktok.com/doc/app-review-guidelines/ . A redirect to `localhost` in the old `scripts/auth_tiktok.py` is not a production callback accessible to the owner's phone or a headless GitHub runner.

After app review allows the desired scope, open the TikTok authorization URL and have the owner sign into the correct creator account and grant the specific scope. Exchange the one-time code with exact redirect URI and app credentials on a trusted server. Save access token, rotating refresh token, expiry and open_id in a persistent private secret store, and set the expected open_id separately. This repository's `tiktok_token_store.py` is a local-file prototype, not a GitHub Actions secret store: ephemeral Actions runners lose the rotated refresh token. Use a persistent encrypted vault/secret manager or another approved durable runtime, and test rotation before unattended operation. TikTok token lifecycle: https://developers.tiktok.com/doc/oauth-user-access-token-management .

`video.upload` uploads to TikTok inbox and the owner finishes from the app. That is *not* public autopublishing. Direct `video.publish` needs TikTok's audit to allow public visibility; unaudited clients are restricted to private posts: https://developers.tiktok.com/doc/content-posting-api-get-started . Keep `config/publish.yaml` on dry run until app, owner account, QA, status receipts and public visibility are verified. Current upload adapter reports an initiation ID, not a verified public post. Track it with `/v2/post/publish/status/fetch/` and avoid retrying uncertain responses; one blind retry can duplicate a post. Public link must be read from the platform, not inferred.

**Once app access exists:** verify the creator handle and open_id, a rights-cleared finished video, caption and destination product link; test one private or inbox upload; inspect status and account visibility; only after public-direct audit and a working readback route enable unattended public jobs. No user-visible publication occurred during this setup work.
